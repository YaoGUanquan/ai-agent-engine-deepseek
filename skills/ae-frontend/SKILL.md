# 前端实现与修复

只执行明确请求的前端范围。在 AI Agent Engine 工程模式中，主控可按职责调用本技能；普通会话仍须用户点名。作为队友时先读 [队友任务约定](references/teammate.md)，不自行扩大范围。

| 模式 | 判定与约束 |
| --- | --- |
| `mode=dev` | 新建或扩展页面、组件和交互；沿用现有技术栈、设计体系和数据访问方式 |
| `mode=fix` | 已有行为报错或视觉异常；先复现和定位根因，再做必要修复，不夹带新功能 |

用户指定模式时以其为准；未指定时从请求和仓库判断。混合请求先恢复受影响行为，再实现已请求的增量；关键意图仍不明确时才提问。

## 实施

1. 检查工作区和目标路径，保留用户改动；读取相关页面、路由、组件、请求封装及测试。
2. 明确入口、用户动作和可观察结果。修复时记录复现条件；开发时确认设计输入和验收条件。
3. 复用项目现有组件、表单、弹窗和状态所有者，避免新建重复请求层或第二份业务状态。
4. 实现加载、空、错误、成功和禁用状态；处理异步竞态、重复提交、失败恢复和路由离开后的资源释放。
5. 对接真实接口契约，核对字段、空值、错误码、分页、认证及权限，不能在前端伪造业务成功。
6. 先运行受影响测试及项目已有类型、构建等检查。涉及渲染或交互时，按 [界面验证](references/ui-verification.md) 核验。
7. 报告变更、根因或设计取舍、实际检查及缺失证据，达到验收后停止。

可增加或修正与改动直接相关的回归测试；不能削弱断言掩盖缺陷。失败先区分产品、测试、规格和环境原因。后端契约需要改变时先说明边界，不默默在客户端绕过问题。

Git 写入、部署、真实数据操作需对应授权。浏览器请求或启动服务前证明数据源是临时测试数据或明确授权的隔离环境；本地地址和现成登录态不代表安全。不得泄露令牌、页面私有数据或认证文件。
