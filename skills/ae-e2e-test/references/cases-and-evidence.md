# 用例与证据

- 先从源码和页面核实路由与选择器；优先可访问名称、角色或稳定测试标识，不依赖猜测文本、元素序号和无依据硬等待。
- 使用框架的等待与重试断言，围绕用户动作和可见结果；必要时核对对应请求及持久状态，不把接口成功替代用户流程。
- 每个用例使用独立可回收的数据与会话，避免共享固定记录。限定超时和并发，仅清理测试拥有的进程、浏览器、账号与临时文件。
- 视口沿用项目设备配置与验收目标，不能统一强制某个分辨率。视觉目标包含相关桌面、移动、加载和错误状态。
- 复用 runner 的截图、trace 和报告目录；认证状态与失败附件不入公开仓库。不要把所有通过用例重跑仅为补充无关录像。
- 记录命令、代码状态、测试范围和附件是否实际打开。分开报告脚本执行、人工或代理视觉检查、后端持久化验证。
- 快照变更必须有明确的预期 UI 变化依据；环境缩放、字体或渲染差异先定位，不能无条件覆盖基线。
