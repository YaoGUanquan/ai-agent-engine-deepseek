# 后端实现与修复

| 模式 | 判定与约束 |
| --- | --- |
| `mode=dev` | 新增或扩展已请求的接口、服务和数据行为，先确认调用方契约 |
| `mode=fix` | 现有错误、数据异常或性能问题，先追踪根因，再实施最小完整修复 |

显式模式优先；否则从请求和当前实现判断。沿用已有授权和验收标准。在 AI Agent Engine 工程模式中，主控可按职责调用本技能；普通会话仍须用户点名。作为队友时先读 [队友任务约定](references/teammate.md)，不自行扩大团队。

## 实施

1. 检查工作区，读取目标路由、服务、数据访问、配置、迁移和测试，识别生产者与消费者。
2. 明确请求与响应、校验、身份与数据范围、错误语义和持久化结果。只询问会改变契约的缺失决定。
3. 修复沿调用链核验现象和根因，区分代码、配置、数据与外部依赖；没有证据时保留假设状态。
4. 实现时复用现有分层与错误处理。数据相关工作读取 [数据与规模](references/data-and-scale.md)，包括无 schema 变更的查询、导出和批量保存。
5. 必要时同步调用方、契约及回归测试，不静默更改分页、总数、权限、同步完成或事务语义。
6. 从聚焦测试开始，按影响范围运行项目已有编译和检查。失败区分产品、测试、规格、环境原因，不改期望值迎合错误实现。
7. 输出变更、契约影响、真实验证结果和剩余迁移或运行风险。普通小改动直接在会话中说明，不强制生成流程文件。

## 验证与授权

默认使用纯测试、合成夹具或测试进程拥有的临时依赖。不得为验证而连接用户管理的数据源；运行服务或接口前证明其数据源属于临时测试环境或明确授权的隔离配置。现成凭据、本地地址及只读 SQL 都不是隔离证明。

认证通过和 HTTP 成功不能证明业务正确或写入已提交；需要验证持久化时检查受影响记录及副作用。静态、隔离测试、真实接口与部署证据分别报告。缺运行条件只阻塞相关验证，不虚报通过。

Git 写入、部署、数据库迁移和真实数据修复分别取得授权。保留密钥、身份信息与原始敏感日志的私密性，不硬编码凭据，不在响应中暴露内部错误细节。
