# 数据与规模

单行 CRUD 只需确认访问路径、唯一性、权限、事务和验证；批量、关联、异步及规模敏感工作再展开下列决策，不强制引入队列、缓存或辅助表。

## 查询与读取

- 从来源到输出追踪 driver 缓冲、过滤、排序、分组、补充查询及序列化；限定驻留项数和字节、查询次数、并发和输出缓冲。分页响应不代表底层工作有界。
- 禁止全量取回后分页、全部解析后分块、无界并发，以及流式读取后再收集全部输出。按页或增量读取，在调度前施加背压，限制缓存并释放游标与连接。
- 明确逻辑行是根实体、关联行还是聚合组；关系条件在分页前参与筛选。水合不得改变根顺序或漏掉权限条件。
- 数据与 count 使用相同租户、权限、删除和过滤范围。不得用本页长度代替精确总数、把 count 失败当零，或通过去重掩盖错误分页。
- 使用确定性排序和唯一 tie-breaker。游标分页是否替代页码、总数是否可近似，取决于现有调用方契约，不能为提速偷偷改变。
- 沿实际 SQL、ORM 和序列化链检查 N+1、关联扇出和必要列；索引存在不证明被使用。查询计划、压测和元数据探测同样需要隔离与对应授权。

## 写入与恢复

- 优先现有的有界集合操作或真实批处理 API；区分 statement batch、driver round trip、ORM flush 和事务 commit，不能仅凭方法名断言已批量执行。
- 批量大小按行宽、绑定限制、内存、锁与超时预算选择，不能规定对所有项目通用的行数。只在允许部分完成时采用分块提交。
- 明确唯一键、幂等、乐观锁、审计和删除语义；新增字段或 schema 沿用项目迁移与 ID 规则，不自行选择业务标识和枚举值。
- 用稳定键或持久 worklist 恢复，不用被修改集合的 offset。覆盖失败 chunk、提交后重试、重复消息与进程中断，不能重复副作用。
- 异步返回仅代表受理：确认持久交接、队列与 worker 上限、重试归属、取消及最终结果。内存任务不等于可靠持久化。
- 权限、状态前置条件和预期影响行数在写入边界校验；不得绕开业务 hook 取得表面吞吐。

## 证据

用隔离夹具覆盖空集、分块边界、重复键、关联扇出、权限排除、相同排序值、部分失败和重试等实际适用场景。独立核对记录集合、顺序、总数、提交结果和资源上限。

记录测量对象、数据规模、命令和实测结果。夹具计数不证明真实 driver 缓冲或堆内存；没有运行证据时保留性能与崩溃恢复风险。
