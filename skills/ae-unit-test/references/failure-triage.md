# 失败归因

结合测试输入、期望来源、实际输出和相关实现定位原因；状态码、异常类型或报错关键词只是线索，不能单独自动决定该改哪一侧。

| 类别 | 所需证据与动作 |
| --- | --- |
| 产品缺陷 | 需求与断言一致，受测行为违反契约；记录最小复现，仅在获准范围内修产品代码 |
| 测试缺陷 | mock、fixture、选择器或期望与有效契约不符；修测试并保留行为约束 |
| 规格冲突 | 需求、调用方和实现不一致且无权威结论；提出具体冲突，等待影响行为的决定 |
| 环境问题 | 依赖、隔离、凭据、工具或配置不足；停止依赖步骤，继续安全的独立检查 |

修复一次针对已定位原因。保留失败日志的脱敏摘要，复跑相关用例；反复失败没有新证据时停止盲目重试并报告阻碍。

不得通过放宽断言、无理由跳过、增加重试或更新快照来掩盖问题。报告 `failed`、`blocked`、`unverified` 与 `passed` 的实际含义，不能把多个代码状态的通过子集拼成最终全量通过。
