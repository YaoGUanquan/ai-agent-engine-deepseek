# 隔离与业务断言

## 执行前

- 从配置引用、测试 runner 和资源创建代码证明测试使用进程拥有的临时依赖或明确授权的隔离环境。`localhost`、`test` 名称、现成凭据和健康检查都不构成证明。
- 不为检查版本、表结构、索引或 SQL 而连接用户管理的数据源。缺隔离、认证或服务时标记阻塞，不把外部数据源当作方便的测试替身。
- 使用项目已有认证载体；从忽略的本地配置或环境引用密钥，不打印值。多角色场景独立保存会话，断言认证和数据范围一起生效。
- 邮件、支付、消息和 webhook 默认使用测试拥有的替身或 sandbox。真实外部副作用不能仅以 finally 清理作为安全保证。

## 业务结果

- 分别核对传输状态、业务错误、响应 schema、状态转换、受影响记录和必要副作用。异步受理须轮询有界终态，不能把 pending 写成完成。
- 校验写入后的读取与提交边界；失败路径核对回滚或允许的部分结果。不能仅断言 ORM 布尔值或 HTTP 2xx。
- 查询覆盖相同过滤下的成员、顺序和总数；认证失败、跨租户、删除记录等不能通过正常 fixture 偶然被遗漏。
- 重试、超时和并发遵循项目契约，限制次数及在途工作。只清理本轮创建且有明确所有权的资源，不执行宽泛删除。
- 报告 runner、隔离机制、命令、收集数量、失败与清理结果。静态契约、隔离服务、真实认证接口和生产验收是不同证据等级。
