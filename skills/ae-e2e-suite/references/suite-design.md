# 套件设计

## 结构与复用

测试源码沿用项目测试根；只有多个用例实际共享逻辑时才抽取 helper、fixture 或页面对象。复用项目已有配置，不创建平行测试体系。

运行报告、trace、截图和覆盖率放项目约定产物目录并加入忽略；视觉基线按项目评审规则管理。鉴权状态独立保存，永不进入公共仓库。不要默默搬动用户已有文件。

## 生命周期与隔离

- 证明服务使用临时测试数据或明确授权的隔离配置再启动；配置名和 loopback 地址不够。缺隔离时停止实际运行，保留静态检查。
- 每个 worker 的账号、数据、端口与临时目录避免互相覆盖，收尾只释放本次创建的资源。共享状态无法隔离的套件串行运行。
- 已有健康服务可在证明隔离和归属后复用，不杀死用户进程。启动等待有上限，失败保留诊断；清理问题不能覆盖首个错误。
- 外部消息、模型、支付和存储使用受控替身或授权 sandbox。真实外部调用需单独门控，不能悄悄退回用户服务。
- 桌面容器应用仅在目标项目确实使用时处理：独立用户数据目录、真实启动入口、进程退出、窗口及显示依赖；不向普通 Web 项目引入桌面支持。

## 持续集成

用已有 package script 和 runner 收集全套用例；限定任务与 worker 并发、总超时及附件保留。分片结果必须全部汇总，不能让失败分片或 setup 错误变成成功。

smoke 与完整套件的选择来自业务风险和既有门禁。失败附件脱敏；缺密钥或目标服务明确失败或标记阻塞，不能以静默跳过冒充全绿。

先验证代表性用例与失败路径，再按变更风险扩大范围。覆盖率仅报告实际采集范围，不凭用例数量估算，也不擅自增加项目没有要求的阈值。
